# 介绍

Future2D 是一个面向下一代 2D 模型、追求开放与互操作的标准倡议。它从一个很实际的现象出发：即使 2D 资产的视觉意图并不复杂，只要离开某个特定的创作工具或运行时，就往往难以继续使用。一个角色可能包含层级、可绘制部件、变形、动画、物理和交互状态，但这些概念在不同生态中的表达方式各不相同。

项目并不打算以行政方式取代现有工具。Future2D 会研究其中已有的能力，识别交换时必须保留的信息，并把边界写清楚。这样，格式可以声明自己表达了什么，运行时可以声明自己计算了什么，转换过程也可以报告哪些内容被保留，哪些内容被有意省略。

## Future2D 正在构建什么

初期工作包括共同术语、模块草案、兼容性证据和参考实现。它们将共同帮助我们回答具体问题：

- 可绘制部件、关节、参数或动画事件的稳定标识是什么？
- 哪些信息属于可移植的模型包，哪些信息属于某个渲染器？
- 当工具不支持某项能力时，怎样声明而不悄悄改变资产？
- 什么证据可以证明模型对某个目标用途来说已经被足够准确地交换？

本站首版说明范围与词汇，不代表已经存在完成的线格式或最终规范。

## 设计原则

- 模型语义应当明确且可移植。
- 目标运行时能力较弱时，应当有可预期的降级方式。
- 规范应当可以用真实资产与工具进行验证。
- 现有生态是证据与协作者，而不是需要抹去的对象。

## 有意收窄的起点

Future2D 从模型在管线中流动所需的共同基础开始：包结构、模型图、动画数据、可选物理行为、运行时求值和验证。并非每个系统都需要全部能力。重点是明确表达缺失与降级，而不是假装所有转换都是无损的。

这对 2D 模型尤为重要。一个文件可能同时包含视觉信息和需要在运行时计算的行为。目标端也许能显示图像，却不能还原参数关系、裁剪规则、约束或事件。因此规范工作会把数据表达与赋予这些数据含义的运行时契约区分开来。

## 如何使用这些文档

在提出字段或转换规则之前，请先阅读核心概念；把规范草案当作正在形成的模块地图，而不是强制性文本。研究某个现有生态时，应记录一个可复现的小型资产、源工具及版本、目标运行时、正在测试的能力和可见结果。这样讨论才会具体，也能让之后的参考实现有可验证的对象。

生态目录是参考资料的目录。Future2D 组织中的 fork 可能用于研究、兼容性测试或原型，并不自动表示它是标准的正式组成部分。
