# 核心概念

Future2D 的第一组术语分别描述模型图、资源和负责求值的运行时，为创作工具、转换器和运行时提供共同的资产描述方式。

## 模型图

模型图包含 2D 模型的层级、几何、材质、约束和命名部件，并记录可绘制对象与变换的附着关系、网格与骨骼的影响关系、遮罩与目标对象的限制关系。

每个可寻址对象都需要在包内拥有稳定标识。另设的显示名称可以本地化，也可以重复。未来模块应区分机器标识、显示名称和对象之间的关系边。

## 资源与包

包是工具之间交换的可移植单元，包含清单、模型数据和纹理等引用资源。清单标明格式版本、可选能力和入口点。可预测的资源引用让运行时能够明确报告缺失资源和不支持的资源类型。

包结构与压缩、传输方式分开。Web 服务器、游戏归档或编辑器项目可以采用不同封装方式，而 Future2D 的包契约仍应识别相同的模型与依赖。

## 求值

求值是把模型数据与动画状态转换为可渲染姿态的过程。运行时可能先解析变换、约束、参数驱动变形、绘制顺序、裁剪和事件，再调用渲染器。文件格式与求值契约需要分开描述，因为数据中的关系不会自动规定求值顺序。

动画向求值过程提供状态。时间线可以改变参数、变换、可见性、变形或命名事件。只要影响结果，格式说明就需要写明插值规则和时间单位。固定帧采样属于有损转换，应当记录。

## 能力与降级

能力是生产端可以输出或消费端可以计算的命名行为。运行时可能支持骨骼变换却不支持网格变形，或能显示遮罩却不支持某种混合模式。Future2D 应让包和运行时能够清楚声明这些能力。

降级是经过记录的替代方式，例如把变形烘焙为采样几何，或用透明占位替换不支持的效果。兼容性报告需要标识降级方式、适用范围，以及外观或行为是否发生变化。

## 交换边界

交换边界是创作工具、文件包与运行时之间传递数据的契约。它定义数据形状、必须理解的语义，以及转换器需要保留或报告为不支持的信息。

交换边界只有可测试才有意义。兼容性案例应记录源资产、源版本、目标、所选能力和预期结果。验证模块将用这些案例区分“解析成功”和“交换成功”。
