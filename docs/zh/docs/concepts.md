# 核心概念

Future2D 的第一组术语将模型图、资源和负责计算它们的运行时分开描述。这些术语刻意保持精简，使创作工具、转换器和运行时可以讨论同一份资产，而不必共享内部实现。

## 模型图

描述 2D 模型的层级、几何、材质、约束与命名部件。模型图不只是场景树：它还记录让部件具有意义的关系，例如附着在变换上的可绘制对象、受骨骼影响的网格，或限制另一个对象的遮罩。

每个可寻址对象都需要在包内拥有稳定标识。名称对人有用，但对转换器并不足够，因为名称可能本地化或重复。未来模块应区分机器标识、可选的人类可读名称以及连接对象的关系边。

## 资源与包

包是工具之间交换的可移植单元，包含清单、模型数据和纹理等引用资源。清单应标明格式版本、可选能力和入口点。资源引用应当可预测，让运行时可以明确报告缺失资源或不支持的资源类型，而不是猜测。

包结构与压缩、传输方式分开。Web 服务器、游戏归档或编辑器项目可以采用不同封装方式，而 Future2D 的包契约仍应识别相同的模型与依赖。

## 求值

求值是把模型数据与动画状态转换为可渲染姿态的过程。运行时可能先解析变换、约束、参数驱动变形、绘制顺序、裁剪和事件，再交给渲染器绘制。明确这一边界能避免常见歧义：文件可以描述关系，却未必定义目标应在何时、以何种方式计算它。

动画是求值的输入，而不只是图片替换列表。时间线可以改变参数、变换、可见性、变形或命名事件。只要影响结果，就必须说明插值规则和时间单位。固定帧采样是一种有损选择，转换器应当报告该事实。

## 能力与降级

能力是生产端可以输出或消费端可以计算的命名行为。运行时可能支持骨骼变换却不支持网格变形，或能显示遮罩却不支持某种混合模式。Future2D 应让包和运行时能够清楚声明这些能力。

降级不代表功能被完整保留，而是经过记录的替代方式，例如把变形烘焙为采样几何，或用透明占位替换不支持的效果。兼容性报告必须标识降级方式、适用范围，以及它是否改变外观或行为。

## 交换边界

交换边界是创作工具、文件包与运行时之间可以传递什么的明确契约。它定义数据形状、消费者必须理解的语义，以及转换器必须保留或报告为不支持的信息。

交换边界只有可测试才有意义。兼容性案例应记录源资产、源版本、目标、所选能力和预期结果。验证模块将用这些案例区分“解析成功”和“交换成功”。
