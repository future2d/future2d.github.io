# 规范草案

Future2D 目前处于研究与草案阶段。以下模块描述预期范围。术语、示例、验证案例和实现影响完成公开评审后，模块才会进入规范性文本。

这些模块分开定义，工具可以先采用其中的子集。跨模块引用必须明确说明依赖关系。例如，动画轨道可以指向模型参数，并沿用模型模块的标识规则。

- **Package**：文件、资源与版本管理
- **Model**：层级、几何、材质与约束
- **Animation**：时间线、插值与事件
- **Physics**：可选的物理行为
- **Runtime**：加载、求值与渲染边界
- **Validation**：一致性与交换测试

## 草案状态

当前网站描述每个模块的边界和待回答问题，尚未发布稳定的 schema、二进制编码或一致性徽章。未来草案中的示例应当足够小，能够人工检查；同时也应当足够丰富，能够暴露正在讨论的行为。

## 草案如何推进

1. **研究**：记录现有生态如何表达某项能力，以及它们的假设在哪里不同。
2. **草案**：用示例说明提议的概念、数据形状和失败行为。
3. **参考实现**：用真实资产和至少一个运行时检验提议。
4. **互操作评审**：比较独立实现，并记录仍然存在的歧义。

在这些步骤完成前，模块属于待评审工作文本。兼容性结论需要对应的证据和实现结果。
