# 兼容性与验证

兼容性工作记录转换后哪些内容可以保留、哪些内容会降级，以及哪些内容必须明确声明。它不是不同工具之间的通过/失败竞赛。一次转换可能足以满足目标用途，却仍然省略了高级效果；关键是让省略可见、可重复并有文档说明。

## 应记录什么

每份报告都应包含：

- 源资产、包和创作工具版本；
- 目标运行时或编辑器及其版本；
- 有意测试的能力；
- 标记为保留、转换、采样、忽略或阻断的能力矩阵；
- 预期的视觉或行为结果；
- 实际结果与可复现步骤链接。

## 解析成功不等于交换成功

运行时能够加载文件，只能证明它理解了足够多的字节并可以继续运行，并不能证明层级、变形、动画时间、裁剪、绘制顺序、物理或事件拥有预期语义。因此验证应同时检查结构化数据和求值后的结果。

对视觉行为来说，小而确定的 fixture 比大型生产模型更有用。对运行时行为来说，应记录输入状态、时间步长、参数和预期事件顺序。当不同平台的精确渲染存在差异时，应定义真正重要的不变量：部件可见性、顺序、参数范围或事件发生。

## 兼容性等级

Future2D 可以把兼容性等级当作沟通工具，而不是营销分数：

1. **结构兼容**：包可解析，标识与资源可以解析。
2. **语义兼容**：目标理解模型关系与能力声明。
3. **求值兼容**：目标对 fixture 生成预期姿态、动画或事件行为。
4. **交换兼容**：独立实现可以消费结果并复现声明的不变量。

报告应标明已经证明的最高等级，并列出低于该等级的边界。
